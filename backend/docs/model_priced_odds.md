# Model priced virtual betting

November 15, 2026. Future markets in the local app now use trained outcome-model probabilities rather than fixed 2.5000 prices. This remains a virtual-point app. Prices are generated by our models, not copied from a bookmaker feed.

## Models and inputs

All sports use StandardScaler followed by logistic regression. The six inputs are the two teams' cumulative prior-day win rates, mean scores and mean scores allowed. NFL/MLB use home/away winner labels; tied games are excluded as training targets and void/refund when settling two-way bets. EPL is now trained on home win, draw and away win as three separate classes, with no binary-probability draw split.

The chronological evaluation fits an earlier approximately 80% date-grouped partition and evaluates a later untouched partition. A separate deployment fit then uses all eligible completed games before the current UTC day. The saved manifest clearly labels the pre-refit evaluation; immutable model artifacts and checksums preserve versions. Prediction/quote feature history ends before the target match's UTC day. A model trained on or after the target date is rejected for that target; completed-game replay remains a separate prior-only binary baseline.

## Price and payout rules

Fair decimal odds = 1 / probability.

Offered decimal odds = 1 / (probability × (1 + margin)), bounded to 1.01–1000.00 and rounded down to two decimals. The target margin is 5% by default; the actual sum of implied probabilities can be slightly higher because of rounding and bounds. The API exposes both the configured margin and the actual implied margin.

At p=0.60 and a 5% margin, offered odds are 1.58. A 100-point stake has a 158-point total return if it wins: 100 stake plus 58 profit. Whole-point payouts round down. Loss returns zero; void/cancellation refunds the stake. Model predictions price the market; actual final scores determine its winning selection.

Prices are refreshed on market reads and placement, with a 60-second unchanged-model quote cache. Refresh prices in the slip clears the current selection so the user can review and confirm it again. Server-side expected_odds rejects changed prices with 409 before debit. Missing models, incompatible outcomes or inadequate history yield unavailable odds; model mode never accepts the legacy fixed-price fallback. Checks run again before bet insertion to prevent crossing kickoff while computing a quote.

Accepted odds and potential_payout are copied into the bet. Each new model-priced bet links to its immutable quote record. Later repricing or model retraining cannot change that accepted contract. Identical request-key retries return the original bet, including after settlement; network/5xx retries retain the original key. Settlement remains idempotent and uses the stored accepted payout.

## Additive setup

Two tables are added: model_market_quotes and model_bet_quotes. The first stores probability, input, price, margin and model-version evidence; the second links accepted bets to their quote. Existing wallets, bets and accepted prices are retained. The local database was backed up to ignored build/backups before this setup. SQL preview: model_odds_schema.sql.

From backend, against the configured authorized local database:

```powershell
python -m app.database.setup_model_odds
python -m app.ml.train_market_models
```

Set these declared settings in ignored backend/.env, then restart the backend:

```dotenv
MODEL_ODDS_ENABLED=true
MODEL_ODDS_MARGIN=0.05
```

MARKET_MODEL_DIRECTORY optionally selects the artifact directory; its default is repository-root build/market-models regardless of working directory. The explicit manifest pins one immutable artifact per sport. Never load model pickles from untrusted sources. The binary baseline paths remain available for historical replay/legacy compatibility; setup never trains a model implicitly.

Old ingestion/demo seed code still creates legacy placeholder prices. With model mode enabled, every eligible market read and every new bet must obtain a valid model quote before those prices can be offered or accepted. Legacy mode stays off/on only by explicit configuration for backwards compatibility; the local running app has model mode enabled.
